MSD 需求管控表

EMS 提需求、MSD 開發、EMS 驗收 —— 這套系統把一筆需求從提出到結案的四個階段、每一次日期異動的理由、以及每週要 review 的逾期項目，全部收在同一張表裡。第一部依你的角色（EMS／MSD／主管）一步一步講「輪到我時要按哪裡」，第二部是逐一功能的完整參考。第一次用請從 A 章 開始。

我的身分

第一部
依角色操作：輪到我的時候要按哪裡

A 章五分鐘讀完整套邏輯；B、C 章分別是 EMS 與 MSD 負責人從頭到尾的操作順序；D 章給主管。每一步都附「詳見第 N 章」，需要細節時再往第二部翻。

A先看這一頁：每個階段只有兩個動作全體

輪到你的時候只要做兩件事：先壓一個預計完成日，做完那天按「做完了」。畫面上其他的紅字、徽章、信件，都只是在提醒你這兩件事。

一筆需求要走四關

階段誰這一關在做什麼
① EMS 規格確認EMS把需求規格寫清楚，交給 MSD
② MSD 確認中MSD看過規格，確認做得了
③ MSD 開發中MSD開發
④ EMS 驗收EMS驗收
⑤ 結案—④ 做完後系統自動結案，不用做任何事

畫面上的 StatusID 就是「現在走到第幾關」。每做完一關，它就往前一格，換下一個人接手。

動作 1
壓預計完成日

在 我的待辦 的卡片上選一天 → 按 存檔。

第一次壓不用寫理由。之後日期快到會提醒你，過了會變紅字。

動作 2
做完了

卡片上按 做完了 → 選是哪一天做完的。

系統會記成準時、提早或延期，然後交給下一關。

還沒壓日期的卡片不會出現「做完了」，所以順序不會弄錯。兩個動作的細節都在第 18 章。

怎麼知道輪到你了

  • 我的待辦 的 「要你處理」有卡片 ＝ 有事要做；空的就是沒你的事。
  • 收到主旨「[需求管控表] 請壓定「◯◯」日期」的信 ＝ 上一關做完了，請你壓日期。可以直接回信問寄件者。
  • 卡片上的紅字「逾期 N 天」＝ 預計完成日過了，還沒按「做完了」。

需求列表上的記號

需求列表一列就是一筆需求。紅色圓圈的編號對照下方說明：

  1. 1左邊的細條：紅＝逾期或沒壓日期；綠＝已結案。
  2. 2⏰ N＝延期完成過 N 次（2 次以上變紅）；🔄 N＝規格回退過 N 次。
  3. 3StatusID＝現在走到第幾關。
  4. 4⚠ N＝這一關的日期被改過 N 次，每次都有寫理由。
  5. 5灰字＋紅字「→ 日期」＝延期完成：灰字是原訂，紅字是實際。
  6. 6⚠ 未壓日期＝走到這一關了，負責人還沒壓日期。
  7. 7✉＝寄信請那一關的負責人來壓日期。
  8. 8逾期 N 天＝日期過了還沒做完。7 天內到期寫「剩 N 天」。
  9. 9結案的列預設看不到。工具列「進度」改「不限進度」就會出現。
看不到 ✎ 🗑 和 ✉？

需求列表只有 MSD 與管理者可以修改。其他人看到的是唯讀版：沒有 ✎ 🗑、沒有 ✉、徽章點不動。EMS 請到 「我的待辦」操作。開了精簡模式時，所有人都是唯讀的。

例跟著走一遍：一筆需求從建立到結案全體

用一筆假的需求（NID 99）走完全程。EMS 的建翰提需求，MSD 的智寬負責開發。每一步開頭的色塊是「這一步誰動手」。

第 1 步　EMS　建立需求

  1. 按 ＋ 新增需求類型分類填 Warning line、子分類填 Tighten，需求補充寫清楚要 MSD 做什麼。
  2. MSD 負責人選智寬EMS 負責人會自動帶出建翰自己。
  3. 「Spec 預計哪天給 MSD？」按 🗓 自選 填 9/05還排不出來就選「先不壓」，之後在我的待辦補。
  4. 按 確認新增系統給它編號 99。

第 2 步　EMS　規格交出去了

  1. 9/05，在我的待辦找到 NID 99 的卡片，按 做完了
  2. 選 今天 09/05按鈕後面寫著「準時」，按下去就存好了。

畫面變成：右上角提示「已移到下面的『追蹤中』，現在輪到 MSD」。

第 3 步　EMS　通知 MSD

  1. 展開「追蹤中」，NID 99 那一列按 ✉ 提醒 MSD視窗會列出收件者智寬、副本建翰。
  2. 按寄出智寬收到「請壓定「2_MSD確認中」日期」的信。

第 4 步　MSD　確認規格

  1. 智寬收到信，在我的待辦的卡片上壓 9/09 → 存檔這張卡已經在他的「要你處理」裡。
  2. 9/09 確認完，按 做完了 → 選 今天③ 也是智寬的，所以卡片留在上面，變成問 ③ 的日期。

第 5 步　MSD　開發，晚了 3 天

  1. ③ 壓 9/25 → 存檔
  2. 開發期間，卡片底下「現況描述」→ 更新例如「主流程完成，待測 CMS 連動」。建翰那邊看得到。
  3. 9/28 才做完：按 做完了 → 選 今天按鈕上寫著紅字「延期 3 天」。系統記成延期完成，延期次數 +1。
9/22 就知道會晚的話

那時就按 還沒，要改日期，改成 9/28 並寫原因。之後 9/28 做完就算準時。兩種做法都會留紀錄，照實記就好。

第 6 步　MSD　通知 EMS 驗收

智寬展開「追蹤中」，按 NID 99 那一列的 ✉ 提醒 EMS。

第 7 步　EMS　驗收、結案

  1. 建翰在卡片上壓 10/05 → 存檔
  2. 驗收通過前，順手填 MP Saving卡片右上 專案資料編輯 ↗ → MP Saving 填 0.5 人/月。結案後卡片就不在「要你處理」了，到時要請 MSD 補。
  3. 10/05 驗收通過，按 做完了 → 選 今天提示寫「已經結案，移到下面的『已結案』」。

走完之後留下什麼

  • 需求列表 NID 99 底下有一顆 ⏰ 1（③ 延期過一次）。
  • 每一關都有完成紀錄：誰、哪一天、準時還是延期。展開那一列的「變更軌跡」就看得到。
  • 兩次 ✉ 通知也都有紀錄。

接下來：EMS 請看 B 章，MSD 請看 C 章，那裡有例外情況（延後、規格變了、按錯了）。

BEMS 負責人：從提需求到驗收結案EMS

你負責 ① 規格與 ④ 驗收，中間的 ②③ 是 MSD 的。全部都在 我的待辦 做，登入後就停在那一頁。

需求列表對你是唯讀的

需求列表可以看全部的需求、搜尋、匯出，但不能修改。分工是：MSD 與管理者在需求列表調整每一筆，你只要專心處理自己的階段。

登入後沒有停在「我的待辦」？代表你的工號還沒建檔，或姓名對不上，請管理者確認（第 18 章）。

B-1 建立一筆需求

  1. 按右上角的 ＋ 新增需求
  2. 填類型分類、子分類兩個都必填。
  3. 需求補充寫清楚要 MSD 做什麼MSD 看的就是這一段。
  4. MSD 負責人：知道是誰就選，不知道就維持「還不確定」之後在卡片右上的 專案資料編輯 ↗ 補。寄信通知 MSD 之前一定要先選好。
  5. 「Spec 預計哪天給 MSD？」選一天排不出來就選 先不壓。不要隨便填一個日期，系統會當真。
  6. 按 確認新增編號 NID 系統會自動給。

如果跳出「編號已被使用，已自動換號」：代表有人同時也在新增。系統已經換好號碼，再按一次「確認新增」就好，其他欄位不用重填。

B-2 壓 ① 的日期

  1. 在「要你處理」找到那張卡片上面寫著「哪天完成？」。
  2. 點一天（例如 下週一），再按 存檔要特定日期就按 🗓 自選。

B-3 規格交出去了：按「做完了」

  1. 有 SPEC 文件連結的話，先在卡片底下「Notes Link」按 貼上沒有連結就不用管，系統會記成「無」。
  2. 按 做完了
  3. 選是哪一天做完的每一顆後面都寫著會記成什麼（準時／提早／延期）。早就做完、只是忘了按，請選 原訂那天。

存好之後，卡片會移到下面的「追蹤中」，換 MSD 接手。

B-4 通知 MSD 來壓日期

  1. 展開「追蹤中」
  2. 那一列右邊按 ✉ 提醒 MSD視窗會列出收件者與副本，確認後寄出。

MSD 沒回應可以再寄一次。系統不會自動寄信，一定要自己按。

B-5 等 MSD 的時候

  • 看進度：「追蹤中」每一列寫著現在哪一關、日期、負責人。點需求名稱可以看 MSD 寫的現況描述。
  • 看到紅字「其中 N 筆已逾期」：MSD 那一關過了日期還沒做完。系統沒有催逾期的信，請直接找人。
  • 看到「還沒壓日期」：按那一列的 ✉ 提醒 MSD。

B-6 驗收，然後結案

  1. MSD 開發完，卡片會回到你的「要你處理」上面寫「④ 驗收」。
  2. 選驗收預計完成日 → 存檔
  3. 順手填 MP Saving卡片右上 專案資料編輯 ↗。結案後卡片就不在了，所以趁現在填。
  4. 驗收通過那天按 做完了 → 選哪一天這筆會自動結案，移到下面的「已結案」。

狀況怎麼做

驗收不過，只是有 bug 要修還沒，要改日期，原因選「技術問題」。修好再驗
規格本身錯了，前面要重做卡片上 🔄 規格回退 ↗ → 選退到哪一關、寫說明（第 06 章）

不建議。改日期會留一筆「日期異動」和你寫的理由，延期完成也會留一筆，主管兩種都看得到。照實記就好。

CMSD 負責人：確認與開發MSD

你負責 ② 確認與 ③ 開發。自己的階段跟 EMS 一樣在 我的待辦 做；需求列表你可以修改，EMS 改不到的事會來找你（C-6）。

C-1 怎麼知道有一筆輪到你

  • 我的待辦 的「要你處理」有卡片。
  • 收到 EMS 寄的「請壓定「2_MSD確認中」日期」的信，可以直接回信問他。

C-2 ② 確認規格

  1. 卡片上選確認的預計日期 → 存檔
  2. 確認沒問題那天，按 做完了 → 選哪一天③ 也是你的，所以卡片會留在上面，換成問 ③ 的日期。
規格有問題，要 EMS 改

不要按「做完了」（那代表確認 OK）。直接跟 EMS 談。確認日會因此延後，就按 還沒，要改日期，原因選「規格變更」。

C-3 ③ 開發

  1. 卡片上選開發的預計完成日 → 存檔
  2. 開發期間，卡片底下「現況描述」→ 更新寫做到哪、卡在哪。EMS 與主管都看得到，通知信也會附上。
  3. 開發完那天，按 做完了 → 選哪一天卡片會移到「追蹤中」，換 EMS 驗收。

C-4 通知 EMS 來驗收

展開「追蹤中」→ 那一列的 ✉ 提醒 EMS → 寄出。系統不會自動寄信。

C-6 只有你在需求列表做得到的事

EMS 看到的需求列表是唯讀的。以下這些他們會來找你：

  • 改任何欄位：那一列最右邊的 ✎ 開編輯視窗。
  • 幫 EMS 撤銷按錯的完成：編輯視窗那一關 ✓ 旁邊的 撤銷。
  • 中間某一關忘了按完成：編輯視窗裡的 補記完成…（第 05 章）。
  • 一次把 ② ③ 都壓好：編輯視窗裡填了 ② 的日期，③ 立刻可以填，一起存。
  • 一次提醒所有需關注的人：需求列表右上「需關注」左邊的 ✉（第 10 章）。

編輯視窗長什麼樣

按資料列最右邊的 ✎ 打開。只會展開「現在輪到」的那一關，其他關收成一行，點名稱就能展開。

  1. 1基本資料：NID 與註冊日期不能改。
  2. 2收起來的關：點名稱展開。✓ 是已經完成的結果。
  3. 3現在輪到：這筆卡在這一關，打開就捲到這裡。
  4. 4🔒 已鎖定：點一下才能改日期。改了要選原因、寫理由。
  5. 5標記完成…：跟卡片上的「做完了」是同一件事。
  6. 6異動紀錄：按「完整軌跡 ↗」看每一筆是誰改的、為什麼。
  7. 7文字欄位：改它們不用解鎖、不用理由。
  8. 8⚙ 進階：平常用不到（第 04 章）。
  9. 9儲存變更：有問題會擋下來並列出是哪幾項。
不要用「手動修正 StatusID」推進度

它在 ⚙ 進階 裡，是修 Excel 匯入資料用的。用它跳關不會留下完成紀錄。正常推進一律用「做完了／標記完成…」。

C-7 每週看一次全部

  1. 需求列表工具列 MSD 選你自己。
  2. 逾期 選「需關注」。
  3. 把網址加到書籤，下週打開就是同一份清單。

D主管與每週會議主管

你不需要按任何寫入的按鈕。要看的是：哪幾筆卡住了、卡在誰身上、整體趨勢。

10逾期與需關注全體

紅字、需關注、逾期篩選、統計報表、我的待辦都用同一套規則，所以數字一定對得上。「今天」以你電腦的日期為準。

系統盯哪一關

  1. 現在這一關（StatusID 指的那一關）沒壓日期 → 就是它，標「⚠ 未壓日期」。
  2. 有壓 → 跳過已經走完的關，取剩下到期日最早的那一關。
狀態意思
⚠ 未壓日期已經走到這一關，負責人還沒排日期。一定算進需關注，排最上面
逾期 N 天日期過了還沒做完
剩 N 天7 天內到期

需關注＝未壓日期＋已逾期＋7 天內到期。結案的、已經走完的關、沒有任何日期可盯的，不會預警。

「走完了沒」只看 StatusID：先把後面的日期都壓好，不代表前面走完了。要讓前一關不再亮紅，請按「做完了／標記完成」。

自己去壓日期

  • EMS、MSD：在 「我的待辦」的卡片上壓。
  • MSD、管理者也可以在需求列表直接點 ⚠ 未壓日期，會打開編輯視窗並跳到那一格。精簡模式下點不動，要先關掉精簡模式。

✉ 寄信請對方來壓日期

  • 在哪裡按：我的待辦「追蹤中」那一列的 ✉ 提醒 ○○；MSD、管理者在需求列表 ⚠ 未壓日期底下的 ✉。
  • 寄給誰：收件者是那一關的負責人，副本給另一邊的負責人。信箱來自指派人員主檔。
  • 用誰的名義：寄件者是按按鈕的你本人，對方可以直接回信。你也會收到一份副本。查不到你的信箱時改用系統信箱（視窗上會寫）。
  • 先確認再寄：視窗會列出寄件者、收件者、副本，按確認才寄。已經通知過的會提醒「這會是第二封」。
  • 系統不會自動寄，存檔後也不會問，一定要自己按。次數不限，每次都會留「通知寄送」紀錄（明細裡「✉ 已通知 N 次」）。
寄送結果

按下去會顯示「寄送中…」，幾秒內會有結果：

  • 已寄出：完成。
  • 尚未確認送出：信交出去了，但系統還不能確定送達。先問對方收到沒，不要馬上再按（可能收到兩封）。
  • 寄不出去：訊息會寫原因與該找誰（第 17 章）。
  • 等太久，已停止等待：不代表沒寄出。按 ⟳ 看明細有沒有多一筆「通知寄送」。

✉ 一次提醒所有需關注的負責人（MSD、管理者）

需求列表「需關注 N」左邊的 ✉：

  1. 按下去先預覽，不會馬上寄列出每封信寄給誰、副本誰、包含哪幾筆。今天已經提醒過的會標出來。
  2. 不想寄的取消勾選沒指派負責人或沒有信箱的會灰掉，並寫明原因。
  3. 按寄出每位負責人收到一封彙整信；副本給另一邊的負責人和你本人。寄完會列出每一封的結果。

為什麼這樣設計

為什麼「做完了」還要問哪一天？延期次數是主管在看的數字。9/19 就做完、10/01 才來按，如果直接記成今天，就變成一次假的延期。

為什麼改日期一定要寫原因？日期被改過幾次也是主管在看的數字。只記「被改了」卻查不到為什麼，紀錄就沒有用。

為什麼壓日期要多按一次「存檔」？壓好之後再改就會記一筆「日期異動」。先選、看清楚再存，比事後改掉好。

為什麼這一頁不能改所有欄位？分工：MSD 與管理者在需求列表調整每一筆，這一頁讓你只專心做自己那一關。這一頁的逾期、日期判斷跟需求列表是同一套規則，兩邊不會打架。

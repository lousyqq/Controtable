第一部
依角色操作：輪到我的時候要按哪裡

A 章五分鐘讀完整套邏輯；B、C 章分別是 EMS 與 MSD 負責人從頭到尾的操作順序；D 章給主管。每一步都附「詳見第 N 章」，需要細節時再往第二部翻。

A先看這一頁：每個階段只有兩個動作

不管你是 EMS 還是 MSD，輪到你的階段要做的事都一樣：先壓一個結束日，做完那天按「標記完成…」。其餘的紅字、徽章、信件，都是系統在提醒你這兩件事。

一筆需求的一生：誰、在哪一階段、做什麼

階段誰這一階段在做什麼你要在系統裡做的兩件事
① EMS 規格確認EMSEMS 把需求規格寫清楚、交給 MSD壓 End Date（預計交規格的日子）→ 交出去那天按 標記完成…
② MSD 確認中MSDMSD 看過規格、確認做得了、怎麼做壓 Confirm EMS Spec Date（預計確認完的日子）→ 確認完按 標記完成…
③ MSD 開發中MSD開發壓 Start／End Date（Start 可不填）→ 開發完按 標記完成…
④ EMS 驗收EMSEMS 驗收壓 Start／End Date → 驗收通過按 標記完成…
⑤ 結案—沒有事要做④ 標記完成後系統自動結案（Status 變 Done）

畫面上的 StatusID 欄就是「現在走到哪一階」—— 每按一次「標記完成…」它就往前一階，棒子就交到下一個人手上。

動作 1
壓結束日

＝承諾「我預計哪一天做完」。在編輯視窗（資料列最右邊的 ✎）那一階段的 End Date 欄填日期，按 儲存變更。

壓好之後系統就會盯著這個日子：快到期灰字「剩 N 天」，過了就紅字「逾期 N 天」。第一次填不必寫理由；之後要改才要。

動作 2
標記完成…

＝宣告「做完了，實際是哪一天」。編輯視窗那一階段標題旁的藍色鈕，會跳一個小視窗要你填實際完成日（預設今天，可以往回選）。

系統拿它比原訂的結束日，記成準時／提早／延期，然後把 StatusID 推到下一階。

兩件事的順序不能反

「標記完成…」這顆鈕只在那一階段已經壓了日期、而且存過檔之後才會出現。所以一定是：壓日期 → 儲存變更（視窗會關掉）→ 做完那天再開 ✎ → 標記完成…。想直接跳到「做完了」也得先補一個日期存檔。

另外不要用「✎ 手動修正 StatusID」來推進階段 —— 那是修 Excel 匯入資料用的，不會留下完成紀錄，主管看到的「延期 0 次」可能只是有人用下拉跳過去的結果。

系統怎麼告訴你「輪到你了」

訊號在哪裡看到代表什麼、該做什麼
一封主旨「[需求管控表] 請壓定「◯◯」日期：…」的信你的信箱上一棒完成了、輪到你壓日期。寄件者是按按鈕的那個人本人，可以直接回信問他。信裡的網址點開就是系統。
紅色徽章 ⚠ 未壓日期資料列的階段時程欄（精簡模式是「目前階段時程」欄）目前走到你的階段，但你還沒壓日期。直接點徽章，編輯視窗會開在那一欄上。
紅字「逾期 N 天」／「今天到期」同一欄你壓的日子到了還沒按「標記完成…」。做完了就去標記；還沒做完就解鎖改日期並留理由（B-2／C-3 有講怎麼選）。

三種訊號背後是同一份規則，所以頁籤上的紅數字、工具列「逾期」下拉的「需關注」、統計報表的「需關注」卡，數字必然一致（詳見第 10 章）。

你會在哪裡按：編輯視窗長什麼樣

按資料列最右邊的 ✎ 開啟。由上而下：

  1. 基本資料：NID、註冊日期、Status、StatusID、Main Cat（專案名稱）、Sub Cat（子項目分類）、MP Saving、EMS／MSD 負責人。
  2. 1_EMS規格確認（Start／End）、然後是需求補充（Remark）與 Notes Link。
  3. 2_MSD確認中（Confirm EMS Spec Date，只有一個日期）。
  4. 3_MSD開發中（Start／End）。
  5. 4_EMS驗收（Start／End）。
  6. 現況說明：目前進度的文字，展開明細與精簡模式都看得到，寄出的通知信也會附上。
  7. 最底下 取消／儲存變更。

每個階段區塊的標題列就是那一階段的「儀表板」：階段名旁邊會依狀態出現 🔒 已鎖定，點此修改（已有日期，防誤改，點一下解鎖）、灰色實心鎖（前一階段還沒填完，先補前面）、藍色 標記完成…（可以按）、或綠色 ✓ 準時完成 · 09/02／紅色 ✓ 延期完成 · 09/20（已經完成的結果，點不動）。底下還有這一階段的異動紀錄一行摘要。

BEMS 負責人：從提需求到驗收結案

你負責 ① 與 ④，中間的 ②③ 是 MSD 的。整條路：建需求 → 壓 ① 的日期 → 交出規格後標記 ① 完成 → 通知 MSD → 等 → 壓 ④ 的日期 → 驗收通過標記 ④ 完成 → 自動結案。

B-1 建立一筆需求

  1. 按工具列右上的 ＋ 新增需求游標會自動停在 NID。
  2. 填四個必填欄位NID（需求編號，自己編、不可重複）、Main Cat（專案名稱）、Sub Cat（子項目分類）、EMS 負責人選你自己。MSD 負責人知道是誰就一併選；還不知道可以先空著，之後任何一方都能在編輯視窗補上 —— 但要 ✉ 通知 MSD 之前一定要先指派。
  3. 「1_EMS規格確認」的 End Date：預計把規格交給 MSD 的日子排不出來就先空著，不要隨手填一個假日期（系統會把它當真，算進逾期與統計）。空著的話系統會把這筆標成 ⚠ 未壓日期 提醒你回來補。
  4. 需求補充（Remark）：把需求內容寫清楚MSD 看的是這一段。
  5. 按 確認新增成功後清單重新載入，新的那一筆會在裡面（預設畫面只看進行中，新需求一定在）。
存完可能會跳一個「要不要寄信通知」的視窗

① 沒壓日期時，系統會問要不要通知「① 的負責人」壓日期 —— 那就是你自己（副本 MSD）。這個視窗是給「幫別人建需求」的情況用的；自己建、自己壓，直接按「取消」就好，什麼都不會寄。

B-2 壓 ① 的結束日、交出規格後標記完成

  1. 壓日期點那一列紅色的 ⚠ 未壓日期（或 ✎），游標會停在 ① 的 End Date。填預計交規格的日子 → 儲存變更。原本是空的，不必填理由。
  2. 規格交出去那天，標記完成✎ → 「1_EMS規格確認」標題旁的藍色 標記完成… → 小視窗裡填實際交出去的那一天（預設今天；隔幾天才來補也可以往回選，系統照實際那天算，不會因為晚按就變延期）→ 確認。
  3. 系統會做的事StatusID 推到 2_MSD確認中、Status 從 Init 變 Ongoing。棒子交給 MSD 了。
  4. 通知 MSD 壓 ② 的日期標記完成之後系統不會自動問要不要寄信。回到清單，那一列 ② 那一格會出現 ⚠ 未壓日期，徽章底下有一顆 ✉ —— 按它，確認收件者是 MSD 負責人（副本是你），按確認就寄出。MSD 還沒指派的話先在編輯視窗指派。MSD 沒回應可以再按，視窗只會提醒你「已經通知過了，這會是第二封」，不會擋你。
日期到了規格還沒交出去，怎麼辦？

兩種做法都正當，看你在哪個時間點：

  • 還沒交、但已經知道會晚 → 改日期：✎ → 🔒 已鎖定，點此修改 → 改 End Date → 選異動原因分類、填文字說明 → 儲存變更。這是「重新承諾」，那一格會掛上 ⚠ 1（改過一次），MSD 與主管都看得到新的日子。
  • 已經交了、只是比原訂晚 → 直接「標記完成…」填實際交出去的日子。系統記成「延期完成」，資料列同時顯示原訂（灰字）與實際（紅字），⏰ 延期次數 +1。

兩種各自計數、互不抵銷。不要為了避開 ⏰ 先把 End 改到今天再標記完成 —— 那會多留一筆 ⚠ 日期異動與理由，主管兩種都看得到。

B-3 MSD 在 ②③ 期間，你可以做什麼

  • 看進度：資料列的 StatusID 欄（2_MSD確認中／3_MSD開發中）與四個階段時程欄看 MSD 壓了什麼日子；點整列展開明細看 MSD 寫的現況描述。精簡模式（工具列右邊）把四個階段收成一欄「目前階段時程」，只留最急的那一階，再加一整欄現況描述 —— 想快速掃過一遍時用它。
  • 催：MSD 該壓的日期沒壓（那一格 ⚠ 未壓日期）→ 按 ✉。壓了但逾期（紅字）→ 系統沒有「催逾期」的信，那種直接找人。
  • 什麼時候輪回你：MSD 把 ③ 標記完成後 StatusID 變成 4_EMS驗收，你會收到「請壓定「4_EMS驗收」日期」的信（MSD 有按 ✉ 的話）。就算沒收到信，那一列 ④ 那一格也會亮 ⚠ 未壓日期，「需關注」也會算進去 —— 每週用 B-6 那條清單掃一次就不會漏。

B-4 驗收：壓 ④ 的日期、驗收通過標記完成

  1. 壓驗收日程點 ④ 那一格的徽章（或 ✎ → 4_EMS驗收），填 Start／End（Start 可不填＝與 End 同一天）→ 儲存變更。End 不可早於 ③ 的結束日；③ 若是延期完成的，欄位底下會有黃字提醒「④ 的完成日下限是 ③ 的實際完成日」—— 把 End 壓在那之後，不然 ④ 之後只能記成延期。
  2. 驗收通過那天標記完成… → 填實際驗收通過的日子 → 確認。
  3. 系統會做的事StatusID → 5 結案、Status → Done。這一筆會從預設畫面消失（預設只看進行中）—— 沒有被刪掉，工具列「進度」改「不限進度」或按 5 結案 就看得到。
  4. 順手填 MP Saving完成後的效益（例：0.5 人/月），✎ → MP Saving → 儲存變更。結案之後也能改，不需要理由。
驗收不過怎麼辦

規格沒錯，只是有 bug 要修 → 什麼都不必回退。StatusID 停在 4，跟 MSD 講好修完的日子，把 ④ 的 End Date 改過去（解鎖、填理由「技術問題」）；修好再驗、通過再標記完成。

規格本身錯了、要重做 → 用 B-5 的規格回退。

B-5 規格變了、前面的階段要重做

  1. ✎ → StatusID 下方 🔄 規格回退視窗裡有沒存的變更會先被擋下，先儲存。
  2. 選退回哪一階段可以選 1 到目前這一階（含）。退回 ② 的意思是「MSD 要重新確認一次」；選目前這一階代表「這一階重做，前面不動」。
  3. 填說明（必填）→ 確認系統會清掉「目標階段（含）以後」的全部日期，🔄 回退次數 +1，退回去的階段重新變成 ⚠ 未壓日期。
  4. 重新壓日期回退之後重填的日期不必填理由（回退那一筆已經帶著說明）。退回 ② 或 ③ 時記得按那一格的 ✉ 通知 MSD 重壓 —— 回退過的階段，系統會把它當成「還沒通知過」，之後存檔也會再問一次。
只是按錯「標記完成…」，不要用回退

回退會清掉日期、回退次數 +1，那是「規格真的變了」的紀錄。誤按了完成鈕請用那個階段 ✓ 旁邊的 撤銷：日期不清、次數不加，StatusID 退回那一階（第 05 章）。

B-6 每週花三分鐘

  1. 工具列 EMS 下拉選你自己的名字。
  2. 逾期 下拉選「需關注」。
  3. 畫面上剩下的就是你這週要處理的：未壓日期的排最上面（去壓，或按 ✉ 催 MSD），再來是已逾期、7 日內到期的（做完了就標記完成，做不完就改日期留理由）。

這個畫面可以直接加書籤 —— 篩選寫在網址裡，下週打開就是同一份清單。

CMSD 負責人：確認與開發

你負責 ② 與 ③。從 EMS 把 ① 標記完成那一刻起這筆就是你的；③ 標記完成後交回 EMS 驗收。中間你會碰到的每一顆按鈕都在這一章。

C-1 怎麼知道有一筆輪到你了

  • 一封主旨「[需求管控表] 請壓定「2_MSD確認中」日期：NID … / 專案 / 子項目」的信。寄件者是 EMS 本人，有問題直接回信；信裡有 NID、分類、現況描述與系統網址。
  • 沒收到信也看得到：工具列 MSD 下拉選你自己 → 逾期 下拉選「需關注」→ 標著 ⚠ 未壓日期 的就是。
  • 更快的訊號：頁籤「需求列表」右上角的紅色數字＝目前需關注的件數（不分人）。

C-2 ② 確認：壓確認日、確認完標記完成

  1. 壓確認日點那一列的 ⚠ 未壓日期（或 ✎ → 2_MSD確認中），在 Confirm EMS Spec Date 填預計把規格確認完的日子。這一階段只有一個日期。
  2. 順手把 ③ 也壓了（可選）填了 ② 的日期之後，③ 的 Start／End 會立刻解鎖 —— 已經排得出開發時程的話，同一個視窗一起填、一次儲存，省得之後再進來一趟。
  3. 儲存變更第一次填不必理由。
  4. 規格確認完成那天✎ → 「2_MSD確認中」標題旁 標記完成… → 填實際確認完的日子 → 確認。StatusID 推到 3_MSD開發中。
  5. ③ 還沒壓日期的話那一格會亮 ⚠ 未壓日期，但 ③ 也是你的階段 —— 不必按 ✉ 寄給自己，直接點徽章去壓。
規格看了有問題，要 EMS 改

不要標記完成（那等於宣告「確認 OK」）。直接跟 EMS 談；他改好之後你再確認。確認日會因此延後的話，解鎖改 Confirm 日期並填理由（分類選「規格變更」）。EMS 要大改規格時由他做「規格回退」退回 ①，你的 ② 會被清空、之後重壓。

C-3 ③ 開發：壓開發日程、完成後標記完成

  1. 壓開發日程✎ → 3_MSD開發中 → Start Date／End Date（Start 可不填，存檔時自動帶成與 End 同一天）。End 不可早於 ② 的確認日。→ 儲存變更。
  2. 開發期間更新「現況說明」編輯視窗最底下那個文字框，寫目前做到哪、卡在哪。EMS 與主管展開明細就看得到，精簡模式是一整欄，通知信也會附上。改它不必解鎖、不必理由。
  3. 開發完成那天標記完成… → 填實際完成日 → 確認。StatusID 推到 4_EMS驗收。
  4. 通知 EMS 來壓驗收日標記完成之後系統不會自動問。回到清單，那一列 ④ 那一格會出現 ⚠ 未壓日期，按徽章底下的 ✉：收件者是 EMS 負責人、副本是你，寄件者是你本人（EMS 可以直接回信）。

沒按 ② 的「標記完成…」就直接按 ③ 的，完成視窗會多列一區「這一次會跳過的階段」，把 ② 列出來、預設勾選、日期預設是 ② 原本壓的確認日（＝記成準時，什麼次數都不動）。② 其實延期的話，把那一列的日期改成真正確認完的那天。不勾的話 ② 就會永遠顯示「已略過此階段」。詳見第 05 章。

開發會延期，怎麼記？
  • 還沒做完、已經知道會晚 → 改日期：✎ → 🔒 已鎖定，點此修改 → 改 End Date → 選異動原因分類、填說明 → 儲存變更。這是「重新承諾」，那一格掛上 ⚠ 1，EMS 與主管看得到新的日子。
  • 已經做完、只是比原訂晚 → 直接「標記完成…」填實際完成日。記成「延期完成」：原訂日保留（灰字）、旁邊多一行紅字的實際日，⏰ 延期次數 +1。

兩種各自計數、互不抵銷。不要為了避開 ⏰ 先把 End 改到今天再標記完成 —— 那會多留一筆 ⚠ 日期異動與理由，主管兩種都看得到，反而更難看。

C-4 驗收不過、要修

  • 小修（bug）：什麼都不必回退。StatusID 留在 4，修完告訴 EMS 繼續驗；④ 的日期要延後由 EMS 改（或你幫他改，一樣要填理由）。
  • 規格錯了、③ 要重做：✎ → 🔄 規格回退 → 選「3_MSD開發中（目前）」→ 填說明。③④ 的日期會被清掉、回退次數 +1，重新壓 ③ 的日期時不必填理由。要連 ② 的確認一起重做就選 ②。
  • 只是按錯「標記完成…」：用 ✓ 旁邊的 撤銷，不是回退（第 05 章）。

核心規則

展開明細後中間那張卡是這筆需求的時程變更軌跡。它不是逐筆列出，而是每個有變更過的階段各一行，改幾次都是一行、不會長高、沒有捲軸：

① EMS規格確認　7 筆 · 延後 35 天　08-21 → 09-05 → 08-21 → ✓09-13 → ↶ → 未填 → 09-19 → 09-25

  • 筆數與淨效果：這個階段一共被記了幾筆，以及「最早的原訂日 → 現在落在哪」差了幾天（紅字延後、綠字提前；「目前未填」表示現在這一階段沒有日期；「回到原訂日」表示改來改去最後又改回去）。延期完成的階段，「現在」是實際完成日。
  • 日期鏈：由舊到新，每一跳就是一筆紀錄。只印月日，滑鼠移到任何一跳上會顯示那一筆的時間、誰改的、類型、改前改後與理由。記號：✓ 標記完成，後面接完成日（紅＝延期、綠＝提早／準時）、↶ 撤銷完成、起 只調了開始日、未填 被規格回退清空。最後一跳是粗體，就是現在的值。
  • 最下面一行是最後一次變更是誰、什麼時候、為什麼（理由太長會截成一行，移上去看全文），以及初始時程是什麼時候填的（各自一行、不截斷）。

要看每一筆的完整內容，按卡片右上角的 完整軌跡 ↗：會開一個用整個螢幕高的視窗，最新的排最上面，一筆一行；頂端可以只看某一個階段。使用者自己填的分類與理由一律印在畫面上（太長截一行、點一下展開全文）；系統自己組的說明（延期／撤銷／重新排程那幾種）收成「說明 ⓘ」，移上去看。規格回退這種一次動到好幾個階段的，仍是一行（標「影響 N 個階段」）。Esc 或點視窗外面關閉。

NID 是需求的唯一編號，重複時會跳視窗提示，請換一個編號。已經被刪除（軟刪除）的 NID 可以被重新使用。

存不進去時

系統會一次列出全部問題，同時把對應的欄位標紅。改好一欄，那一欄的紅字就會自己消失，不必反覆按儲存試錯。

04編輯需求與壓日期

按資料列最右邊的鉛筆圖示開啟編輯視窗。視窗裡的四個階段各自獨立：各自解鎖、各自填理由、各自寫軌跡。

負責人與信箱

EMS／MSD 負責人是下拉選單，名單來自指派人員主檔。選好之後，下拉底下會用灰字顯示這個人的信箱（例：✉ Sariel_Lin@UMCG）—— 要聯絡負責人時不必再另外去查。

信箱是唯讀的

信箱不能在畫面上修改，人員名單與信箱一律由管理者直接在資料庫維護。那個人沒填信箱時，這行灰字整個不出現。

下拉選單裡一定找得到這筆目前已經指到的人，就算他已經被停用 —— 否則一按儲存就會把指派靜靜清掉。

這個限制只擋「從空白開始填寫」。已經有值的欄位一律照舊，解鎖後就能改 —— 舊資料裡有階段跳空的（③ 有日期但 ② 空），那些列不會因此被鎖死。

改日期一定要留理由

必填

把一個已經壓好的結束日改掉時，必須選一個異動原因分類（規格變更／優先級調整／技術問題／其他）並填文字說明，兩者缺一不可儲存。

不需要理由的情況：只改了開始日、解鎖了但沒動結束日、或是第一次填寫這個結束日。

異動會寫進稽核軌跡，在展開明細的「時程變更軌跡」與編輯視窗的「異動紀錄」都查得到，並讓那一格的 ⚠ N 加一。

日期的先後限制

  • 同一階段內：結束日不可早於開始日（同一天可以）。日期選擇器會直接把不合法的日子反灰。
  • 跨階段：① End ≤ ② Confirm ≤ ③ End ≤ ④ End。只檢查這次被你動到的那一組 —— 舊資料裡本來就倒著填的，不會因此連現況描述都存不了。
  • 改掉結束日時，該階段的「實際完成日」會一併清空（原訂日重排之後，原本的落差就不成立了）。⏰ 延期次數不會跟著減，那是已經發生的事實。
  • 已經走完的階段（StatusID 已經在它後面）不可以把結束日清空；要退回那個階段請用「🔄 規格回退」。
  • 清空不可以留下缺口：② 有日期、③ 也有日期時，不能只清 ②（會變成「② 空、③ 有」）。先清掉後面的階段，或改用「🔄 規格回退」。這兩條也只擋「原本有值、這次被你清空」的情況，舊資料本來就有洞的不受影響。
關閉前會問你

視窗裡有未儲存的變更時，按 Esc／✕／取消都會跳確認。改回原值再關則不會問。

存檔之後可能會再問一句：要不要通知下一棒？

儲存成功後，只要這筆需求當前那一階段還沒壓日期、該階段的負責人查得到信箱、而且這個階段還沒通知過他，就會跳出一個視窗問要不要寄信通知他。 按「取消」不會寄任何東西。完整說明見第 10 章的「✉ 寄信通知下一棒來壓日期」。

同一個階段通知成功一次之後，之後再存幾次檔都不會再問。日期壓上去之前你可能要為了別的欄位存好幾次檔，每次都問同一件已經做過的事只是干擾。要再催一次隨時可以按那一格的 ✉。

負責人還沒指派、或人員主檔裡沒有他的信箱時，這個視窗不會跳（跳了你當下也修不了 —— 信箱只能由管理者在資料庫補）。那一格的 ✉ 仍然在，按下去會明講缺的是什麼。

05標記完成

每個階段標題旁的 標記完成… 鈕。這是推進 StatusID 的正常路徑。

先分清楚：藍色的是「要你按」，綠色的是「已經完成了」

階段標題旁邊那顆小藥丸有兩種，顏色與文字都不一樣：

  • 藍色框的 標記完成… ＝ 還沒完成，可以按。結尾的「…」代表按下去會跳一個視窗（要填完成日）。
  • 綠色的 ✓ 提早完成 · 09/02（或紅色的 ✓ 延期完成 · 09/20）＝ 已經完成的結果，點不動。後面那個日期就是實際完成日，把滑鼠移上去可以看到完整日期、是誰標記的、以及是不是補登的。

（2026-09-10 以前這兩顆都是綠色的、也都帶 ✓，只差一條幾乎看不見的邊框，很容易看錯狀態。）

按下去要先填「實際完成日」—— 不必當天就來按

按 標記完成… 會先跳一個小視窗，裡面有一個實際完成日欄位，預設帶今天。 填的是事情真正做完的那一天，不是你來平台按按鈕的日子。

例：原訂 9/9 完成，使用者也真的 9/9 做完了，但你 9/20 才來更新 —— 把日期選成 9/9，系統就記成「準時完成」；不會因為你晚了 11 天才來按就變成延期。

可以選的範圍：最晚到今天（不能填未來）；最早是下面兩個裡比較晚的那一個 —— 前一階段實際結束的那一天（它的結束日；若它是延期完成，就是它的實際完成日 —— 這一階段不可能比前一階段更早完成）， 或半年前（同一個日，例：9/11 → 3/11；月底對不上就取那個月的最後一天，8/31 → 2/28；補登不會無限往回）。 視窗底下會直接寫出目前可選的區間，以及實際生效的是哪一個下限。

開始日不是下限。開始日沒填時存檔會自動帶成與結束日同一天，所以「原訂 9/15、其實 9/9 就交了」這種補登， 完成日 9/9 會早於（自動帶入的）開始日 9/15 —— 照樣可以選，系統會把開始日一併調整成 9/9，視窗上會先寫出來。

選了不是今天的日期時，稽核紀錄會標成「完成日 2026-09-09，於 2026-09-20 補登」—— 這樣日後查得到「這筆是事後補登的、誰補的」。

系統拿你填的那一天去比對這個階段原訂的結束日，視窗裡會即時顯示會被記成什麼：

完成之後解鎖改結束日（② 是確認日）是可以存的，但完成紀錄與次數不會跟著變：提早／準時完成的那顆 ✓ 旁邊會多一行黃字「（結束日之後已改為 X）」， 軌跡上那筆「日期異動」的說明也會寫明「此階段已於 … 標記完成」；延期完成的話「→ 實際」那一行會被清掉、⏰ 次數保留（軌跡會寫「先前記錄的實際完成日已一併清除」）。 完成日填錯了，正確的做法是「撤銷」再重新標記完成 —— 那條路才會把次數算對。

另外，若前一階段是延期完成的（例如 ③ 原訂 9/10、實際 9/15 才完成），把 ④ 的結束日壓在 9/15 之前也存得進去， 但欄位底下會出現黃字提醒：④ 的完成日下限是 9/15，之後只能記成延期 —— 建議把日期改到 9/15 之後。

延期完成怎麼呈現

資料列上會同時顯示原訂（灰字）與下一行的 → 實際（紅字）。原訂日期不畫刪除線 —— 它並沒有被改掉，主管要看得到落差。

成功之後會連動兩件事：

  • StatusID 前進一階（①→2、②→3、③→4、④→5），只前進不後退。已經在 ④ 的案子回頭補按 ① 的完成，不會被拉回 2。
  • Status 連動：推到 5 時自動變 Done；離開第 1 階段時 Init → Ongoing。

跳過中間的階段時，可以一併把它記成完成

你如果還沒按 ② 的「標記完成…」，就直接去按 ③ 的，那麼 ② 這一階段從頭到尾都不會留下完成紀錄 —— StatusID 會從 2 直接跳到 4，② 之後就只會顯示灰字已略過此階段。

所以完成視窗上會多出一區「這一次會跳過的階段」，把那些階段列出來：

  • 預設就是勾好的，日期預設帶那個階段原本壓的日期。那等於「準時完成」—— 提早／延期次數都不會變，日期欄位也一個字都不會改，只是替它補上一筆完成紀錄與 ✓ 標籤。
  • 那個階段其實有延期的話，就把日期改成真正做完的那一天。改成晚於原訂日就會記成「延期完成」並讓 ⏰ 次數 +1 —— 這才是對的，記成準時等於把一次延期抹掉。
  • 不想記錄就取消勾選。那一列旁邊會直接寫出後果：這個階段之後會顯示「已略過此階段」。
  • 一併記錄的階段不會改變 StatusID，StatusID 仍然只由你按的那一顆決定。
可以填的日期範圍

每一列都不可能比前一階段更早完成，也不可能比後一階段更晚完成，最晚一樣只到今天。 超出範圍時那一列會標紅字寫出可選區間，確認完成 會變灰。

你改了主要的完成日，下面那幾列的可選範圍會跟著即時變動。

反過來也會動：你把前一個階段勾起來一併記錄時，上面那個「實際完成日」的下限也會跟著放寬 —— 因為那個階段的日期正由你在同一個視窗裡填，不必再拿它原本壓的日期來卡你。 舉例：② 原訂 9/8、③ 原訂 9/15，而 ③ 其實 9/5 就做完了 —— 只要把 ② 一起勾起來（填 9/3），③ 就填得進 9/5。不勾的話，③ 最早只能填到 9/8。

勾了卻沒有被記錄時，成功訊息會講出來

如果你的畫面停留比較久，中間別人已經把某個階段標成完成了，那一階段不會被重複記一次 —— 你按的那個階段照樣完成，成功訊息裡會多一句「◯◯ 不需要重複記錄」告訴你哪幾階被略過了。 按 ↻ 重新整理就會看到它已經有 ✓ 了。

只涵蓋「這一次會跳過的」；更早的用「補記完成…」

這一區只列出從目前 StatusID 到你按的那一階之間的階段。 更早以前就已經變成「已略過此階段」的資料（匯入來的、或以前直接按了後面的階段）， 灰字旁邊會有一顆 補記完成…，見下一段。

已經走過但沒有完成紀錄的階段：用「補記完成…」

階段標題旁顯示灰字「已略過此階段」時，旁邊會有 補記完成…。按下去的視窗與「標記完成…」一樣要你填實際完成的那一天，差別只有：

  • StatusID 完全不動（它早就走到後面了），只補一筆完成紀錄，並依你填的日期計提早／延期。
  • 日期預設是原訂日（＝準時、不計次），不是今天 —— 那個階段多半是很久以前的事，預設今天幾乎必然是一次假延期。真的延期或提早，請改成實際的那一天。
  • 可選範圍多一道上限：不可晚於下一階段實際結束的那一天（這一階不可能比後一階更晚完成）。前一階段的實際完成日晚於下一階段的日期時（匯入來的倒序資料）按鈕不會出現，tooltip 會寫明要先修哪兩個日期。
  • 軌跡上那筆會標「事後補記：StatusID 已在 X，不變」；之後用「撤銷」撤掉它時，StatusID 同樣不會退。

規格真的變了、這個階段要重做，才用「🔄 規格回退」—— 那條路會清掉日期並讓回退次數 +1，不是補紀錄的工具。

沒有出現「標記完成…」鈕時，畫面會告訴你原因

順序灰字訊息意思與處理
1已略過此階段StatusID 已經走過這一階段了。下次要避免：按後面階段的完成時，視窗上會問要不要一併記錄（見上一段）。已經變成這樣的資料：旁邊那顆「補記完成…」可以補上完成紀錄，StatusID 不動（見上一段）。「規格回退」是給規格真的變了、要重做的情況用的，不是補紀錄的工具。

三個限制

同一階段不可重複標記完成（否則計數會變成假數字）。回退或撤銷之後可以重新標記。

視窗裡改了日期還沒儲存就按完成會被擋下 —— 它會拿舊值比對，結果與畫面對不起來。請先儲存。

完成成功後視窗會關閉並重新載入這筆資料，所以視窗裡任何沒存的欄位都會遺失。系統會先擋下並要求你儲存。

誤按了「標記完成…」：用「撤銷」

標記完成之後，那個階段的標題旁會出現 ✓ 提早完成 · MM/DD（或延期完成）的結果標籤；最後一次標記的那個階段旁邊會多一顆 撤銷。按下去會先列出撤銷後會發生什麼，說明可填可不填。

項目撤銷會做什麼
StatusID退回那個階段自己（例：③ 標記完成後 StatusID 是 4，撤銷後回到 3）。退出「結案」時 Status 由 Done 轉回 Ongoing。
提早完成結束日（② 是確認日）還原成原訂日；提早次數減 1（準時完成當初沒有加過，就不減）。標記完成之後你又改過那個日期的話，就維持你改過的值。提早完成時被一併調整過的開始日也會還原 —— 但若你改過的結束日比原本的開始日還早，開始日就維持不動（否則會變成開始日晚於結束日）；開始日在完成之後被你改過的，同樣維持改過的值（軌跡會寫「開始日在標記完成之後已被改成 X」）。這幾種情況撤銷視窗都會在按下去之前逐條寫出來（「維持改過的值、不還原」「開始日維持 X：原本的 Y 晚於目前的結束日 Z」），軌跡上也會寫明。
延期完成清掉實際完成日；延期次數減 1。原訂日本來就沒動。
原訂日期一律不動。這是它與「🔄 規格回退」最大的差別 —— 回退會把日期清掉、回退次數 +1；撤銷不會。
軌跡多一筆「撤銷完成」，原本那筆完成紀錄仍然看得到（一筆都不刪）。撤銷之後可以重新按「標記完成…」。
一次只撤一筆，從最後一筆開始

按 ③ 完成時一併記錄了 ②，撤銷第一次退的是 ③（你真的按下去的那個）、再按一次才輪到 ②。要退回更前面的階段、或規格真的變了要重做，請用「🔄 規格回退」。

看到「資料已被其他人修改」：你開著視窗的期間，別人已經把另一個階段標記完成（或改了 StatusID）。系統不會撤銷到對方剛做的那一筆 —— 關掉視窗重新載入，看過最新狀態再決定。「🔄 規格回退」也有同一道保護。

「現在不能撤銷：還原後日期會倒序」是什麼意思

提早完成會把結束日改成完成日；之後你可能已經把下一階段的日期壓在那之後、但比原訂日還早（例：① 原訂 09/10、09/01 提早完成，② 接著壓 09/03）。這時撤銷會把 ① 還原成 09/10，比 ② 的 09/03 還晚 —— 後面的階段跑到前面去了，之後那兩格會互相卡住改不動。所以撤銷視窗會標紅、「確認撤銷」按不下去。

解法：先把下一階段的日期改到原訂日之後（或先清掉），再回來撤銷；若那個階段真的要重做，改用「🔄 規格回退」。

06規格回退

規格變更導致前面的階段要重做時使用。入口在編輯視窗 StatusID 下方的 🔄 規格回退（StatusID ≥ 2 才會出現）。只是誤按了「標記完成…」請用「撤銷」（第 5 章），不要用回退 —— 回退會清掉日期、回退次數還會 +1。

  1. 先儲存視窗裡未存的變更系統會在開啟回退視窗之前就擋下，不會讓你挑完階段、打完說明才說不行。
  2. 選要退回哪一個 StatusID可選 1 ~ 目前這一階段（含）。選目前這一階（按鈕標著「（目前）」）時 StatusID 不會動，只清掉這一階（含）以後的日期重新排程 —— 例：StatusID 3、③④ 都壓了日期、規格變了要重做 ③，就選 ③；不必退到 ② 把已經確認完的 ② 一起清掉。
  3. 填寫文字說明（必填）異動原因分類固定記為「規格變更」，不需要選。
  4. 確認視窗關閉並重新載入這筆資料。

07手動修正 StatusID

StatusID 預設是唯讀的彩色藥丸。正常只由「標記完成…」與「🔄 規格回退」兩條路推進。

階段填錯（尤其是 Excel 匯入來的資料）時，按 ✎ 手動修正 StatusID 開放下拉。

只能往前，不能往回

下拉裡比目前 StatusID 小的階段是灰的、選不到。要退回前面的階段只有兩條路：規格變了要重做 → 「🔄 規格回退」；誤按了「標記完成…」 → 該階段旁的「撤銷」。直接改回去會留下一個「已經記成完成、StatusID 卻還沒走到」的階段，畫面上的紅字與次數就對不起來了。「未設定」這個選項也已經拿掉：StatusID 一定要有值。

分類與說明兩者都必填

手動改 StatusID 一定要留痕跡，否則主管看到的「延期 0 次」可能只是有人用下拉跳過去的結果。改 Status 則不必填理由（它是人工壓的旗標），但一樣會寫進軌跡。

Status 的 Done 只能配 StatusID 5 結案

Done 代表結案，會讓這筆需求從「需關注」、⚠ 未壓日期、✉ 通知、逾期篩選全部退出、統計算進已完成。所以 Status 選 Done 時 StatusID 必須是 5 結案，反過來 StatusID 是 5 時 Status 也必須是 Done —— 兩邊對不上，Status 欄會標紅、存不了。

正常不需要自己動它：④ EMS驗收 按「標記完成…」會自動把 StatusID 推到 5、Status 改成 Done；要重開已結案的需求用「🔄 規格回退」，它會自動改回 Ongoing。匯入資料階段填錯時，把 StatusID 手動調到 5，Status 會一併改成 Done（欄位底下會寫出來）。

前置階段沒填完就不給改

把 StatusID 設成 N，語意就是「1 ~ N-1 都已經走完」，所以那些階段的結束日必須齊全：

目標 StatusID必須已填的結束日

3① + ②
4①② + ③
5①②③ + ④
  • 缺什麼會在你選了階段的當下就列出來（紅色面板取代原因欄），不是等按了儲存才說。
  • 不檢查目標階段自己 —— StatusID = 4 的語意是「正在驗收」，這時驗收日還沒排是正常的。
  • 判定用視窗當下的值，所以「在同一個視窗裡補完 ③ 的日期再把階段改成 4」可以直接存。
  • 手動調整不動三個計數欄，也不會補寫該階段的完成紀錄，差異只留在軌跡裡。

08刪除需求

按資料列最右邊的垃圾桶圖示。這是軟刪除 —— 資料庫保留紀錄，只是不再出現在清單上。

刪除原因必填

確認視窗有一個必填的「刪除原因」，沒填時「確認」鈕是停用的。訊息會寫明是哪一筆（NID／專案名稱／子項目分類），並提醒此編號之後可以再被使用。

刪除會寫一筆稽核紀錄（誰、什麼時候、為什麼），供日後查帳追溯 —— 但那筆紀錄不會出現在畫面上，需要時請從資料庫查詢。刪除是唯一讓整筆資料從清單消失的動作，所以特別要求說明理由。

09搜尋、篩選與排序

搜尋框比對哪幾欄

工具列最左邊那個搜尋框，會拿你打的字去比對這七欄（不分大小寫、只要包含就算命中）：

  • NID、Main Cat、Sub Cat
  • EMS 負責人、MSD 負責人
  • 現況描述、需求補充（Remark） —— 這兩欄是展開明細裡的那兩段長文字

把滑鼠移到搜尋框上，這份清單也會直接顯示出來。

日期、Status、StatusID 不在搜尋範圍

那三種請用搜尋框右邊的漏斗 🔻（欄位篩選）—— 它會在表頭下方開一排輸入框，可以逐欄過濾。搜尋框刻意不比對日期：一個關鍵字同時比對日期字串只會做出一堆巧合命中（例如打 2026）。

Notes Link 也不比對 —— 那欄存的是網址，比對只會撞到網域這種到處都有的字。

預設只看進行中

一打開需求列表，畫面預設只顯示尚未結案的需求（進度：進行中）。已結案的那些沒有消失，只是不在預設畫面上 —— 目前 63 筆裡有 45 筆已結案，全部攤開的話，你今天真正要處理的那十幾筆會被埋在裡面。

要看到全部，任選一種：

  • 工具列的 進度 下拉（就是那顆藍色的「進度：進行中 (19)」）改成「不限進度」。
  • 按階段統計鈕最左邊的 ALL —— 它同時清掉已選的階段與「只看進行中」。
  • 直接按 5 結案（或任何被「進行中」整群擋掉的階段）—— 系統會自動幫你取消「只看進行中」，不會讓你點到一個必然 0 筆的組合。

階段統計鈕上的五個數字一律不受「進度」影響（5 結案 永遠寫著真實的 45），每個數字就是「按下去會看到幾筆」。

那一排的右邊還有 需關注 N（只印總件數；未壓／逾期／7 日內各幾件在它的滑鼠提示與「逾期」下拉裡）、顯示 N / M 筆、ⓘ（圖例）、精簡模式、排序。圖例預設是收起來的 —— 那條符號說明只有第一次需要，按 ⓘ 就展開（會記住你的選擇）。列印時無論收合與否都一定會印出來，因為紙上沒有滑鼠提示，⏰／🔄／⚠ 只剩圖例解釋得了。

搜尋時不會漏掉已結案的

搜尋結果若有幾筆被「只看進行中」擋住，條件晶片列會出現一行 「另有 N 筆已完成的需求符合『你打的字』」 與一顆 一併顯示。按下去就把它們一起列出來。

系統不會自作主張幫你把範圍改掉 —— 筆數自己跳動的話，你會分不清當下看的是哪一群。

條件晶片列

表格正上方會把目前生效中的每一個條件列成一顆晶片，每顆都有自己的 ✕ 只移除那一條。它解釋的是「下面這 N 筆是怎麼來的」。預設的 進度：進行中 也是一顆晶片 —— 系統替你套的條件，畫面上一樣看得見、一樣拿得掉。

只剩「預設只看進行中」這一個條件時，晶片列在螢幕上不出現 —— 那時工具列的 進度：進行中 (19) 已經是全畫面唯一的藍色實心控制項，筆數也寫在上面，它自己就是移除的入口（改成「不限進度」）。一旦你加了第二個條件，晶片列就會展開成表格正上方的獨立一列，把每一條都列出來。紙上兩種情況都會印出條件（紙上沒有工具列，所以那份一定要印）。

留意標成紅框的晶片

精簡模式收起來的欄位（Status／註冊日期／MP Saving／四個階段時程）與一般模式沒有的欄位（目前階段時程／現況描述），它們的欄位篩選值照樣在過濾。那些晶片會標上 ⚠ 與紅框，列尾也會寫一句「有 N 個條件的欄位在目前模式下是收起來的，但它仍在過濾」。

這就是「看不到條件卻筆數變少」的答案。

10逾期與需關注

每週會議要 review 快到期的需求。整套判定只有一份規則，所以畫面上的紅字必然對得上工具列與統計報表的數字。「今天」以你電腦的日期為準（頁首「畫面」時間的提示會寫出來）；分頁開過午夜會自己換日，不必重新整理。

系統怎麼挑「該關注的那個階段」

  1. 目前這一階段（StatusID 指的那一個）壓日期了沒？沒壓 → 就是它，標成「⚠ 未壓日期」，不再往下找。
  2. 有壓 → 排除已經走完的階段。
  3. 剩下已經壓了日期的階段裡，取到期日最早的那一個。

挑到的不是 StatusID 對應的那一階段時，畫面會標「最急 · 階段名」—— 代表目前那一階段還沒排日期，或它的到期日比較晚。

⚠ 未壓日期＝已經到那一階段，卻還沒排日期

最常見的產生方式：按了「③ 完成」，StatusID 推進到 4，但 ④ 的驗收日還是空的。這種列不受 7 日窗限制，一定會被列入需關注，並排在「逾期優先」的最上面。資料列上那一格會同步標紅色的「⚠ 未壓日期」徽章 —— 每一件被算進去的，畫面上都看得見原因。

StatusID 空白或超出 1~5 的資料一律不推斷（空白代表「不知道走到哪」，硬猜會冤枉一批舊資料）。

要自己把日期壓上去：直接點那顆徽章

「⚠ 未壓日期」徽章本身就是按鈕。點下去會開啟那一筆的編輯視窗，並自動捲到、聚焦在那一階段的日期欄位上 —— 系統已經知道卡的是哪一階段，不必再自己在四個區塊裡找。填好日期存檔即可（原本是空的，不必填異動理由）。

徽章下方那顆 ✉ 是另一件事：那是通知別人來壓（見下一節）。點徽章與點 ✉ 都不會展開那一列。

前一階段還沒填完而被鎖住時，畫面一樣會捲到那一格，你會看到那個欄位是鎖著的、旁邊寫著要先填完哪一階段。

精簡模式下這顆徽章「點不動」，那不是壞掉

精簡模式是唯讀的主管檢視，整個「操作」欄（編輯／刪除）都收起來了，這顆徽章也一樣不能點。 兩種模式的徽章長得一模一樣，所以看起來很像功能失效 —— 把滑鼠移上去，說明會告訴你目前點不動。

要壓日期就先把精簡模式關掉（工具列右邊那顆 精簡模式），一般模式下的徽章按下去就會跳到日期欄。 ⚠️ 視窗寬度在 1024px 以下時會強制精簡模式（開關會反灰、標著「· 窄螢幕」），那時要把視窗拉寬才能關掉。

徽章下面那顆 ✉ 兩種模式都能按 —— 它是通知別人來壓，不是自己改資料。

✉ 寄信通知下一棒來壓日期

「⚠ 未壓日期」的意思就是「輪到某個人了，但他還沒排」。系統可以直接把這句話寄給他 —— 收件者是那一階段的負責人，副本給另一邊的負責人。例如 ④ EMS驗收 沒壓日期， 就寄給 EMS 負責人、副本給 MSD 負責人。信箱取自指派人員主檔（就是編輯視窗負責人下拉底下那行灰字的來源，見第 04 章）。

怎麼觸發會發生什麼
儲存之後自動問 按下「確認新增」或「儲存變更」而且存檔成功之後，只要這筆需求當前那一階段還沒壓日期、收件者查得到信箱、而且這個階段還沒通知過這個人，就會跳出一個視窗問要不要通知。按「取消」不會寄任何東西，那一格的 ✉ 隨時可以再按。
負責人還沒指派、或人員主檔裡沒有他的信箱時，這個視窗不會跳 —— 那是要管理者去資料庫補的，不該擋在你每次存檔的最後一步。
那一格的 ✉ 手動寄 資料列上「⚠ 未壓日期」徽章正下方有一顆小小的 ✉，點它會跳出完全一樣的視窗。精簡模式的「目前階段時程」欄也有同一顆。點 ✉ 不會展開那一列。
這一顆永遠都在：收件者沒指派、或沒有信箱時，按下去會明講缺的是什麼、該去哪裡補 —— 你主動要寄，系統就一定要回答你寄了沒。
同一個階段，系統只會自動問你一次

只要這個階段已經成功通知過現在這位收件者，之後再存檔就不會再跳那個視窗了。日期壓上去之前你可能要為了別的欄位存好幾次檔，每次都被問同一件已經做過的事，久了只會養成「看到就按取消」的習慣 —— 那反而會讓真正該響的那一次也被一秒關掉。

下面三種情況會重新開始問，因為它們都代表「有人還不知道這件事」：

  • 階段往前走了（例如 ② 通知過，推進到 ③ 又沒壓日期）—— 那是另一個人要壓的日期，他從來沒收過信。
  • 換了負責人而日期還是沒壓 —— 新接手的人沒收過那封信，完全不知道有這件事。系統會針對新的收件者重新問一次。
  • 那個階段被「🔄 規格回退」退回來 —— 日期被清空、要重新排一次，等於重新輪到他。

另外，「尚未確認送出」（見下方）不算通知成功，系統下次存檔還是會問你 —— 因為那封信到底有沒有送到，系統自己也還不確定。

手動的 ✉ 完全不受影響，永遠按得下去。若這個階段已經通知過同一個人，視窗上會多一行提醒你「已經在某月某日通知過了，這會是第二封」—— 只是告訴你一聲，不會擋你。對方沒回、需要再催一次是很正常的事。

這封信是用「你本人」的名義寄出去的

寄件者就是按下按鈕的那個人 —— 系統拿你的 Windows 帳號（剝掉網域之後就是工號）去指派人員主檔比對 EMPO，找出你的信箱。所以收件者可以直接回信問你，不是回給一個沒人看的系統信箱。

你的工號不在名單上、或那一筆沒填信箱時，會退回管理者設定的系統共用信箱，視窗上會直接寫「系統預設信箱」，信的落款也會改成「請勿直接回覆本信箱」。兩種都寄得出去，只是回信的對象不一樣。

用模擬帳號時一律走系統信箱，不會用被模擬的那個人的名義寄信。

你自己也會收到一份副本（用本人名義寄出時）。這封信是系統直接送出去的、不會出現在你的寄件匣，所以系統會把你加進副本讓你留底；視窗上會寫明「你自己也會收到一份副本」。你本來就是收件者或副本時不會重複寄；走系統信箱時系統不知道你是誰，也不會有這份副本。

信裡那行「需求管控表：http://…」可以直接點開系統（信同時附純文字與 HTML 兩種格式，看得到 HTML 的郵件軟體就會顯示成超連結）。

視窗上會先把寄件者、收件者與副本的姓名和信箱完整列出來，確認過再按「確認」才會真的寄出。 寄出後會在那筆需求留下一筆「通知寄送」紀錄，寫明什麼時候、誰按的、寄給了誰 —— 所以「這件事到底催過沒有」在系統裡查得到。

催幾次都可以，紀錄不會把軌跡洗版

手動的 ✉ 沒有次數限制，對方沒回就再催一次。每一次都會留紀錄，但那些紀錄不會混進「時程變更軌跡」的時間軸 —— 它們收在軌跡卡片上方的一行裡（「完整軌跡」視窗裡也不列，只在標題計數）：

✉ 已通知 5 次 · 最後 2026-09-02 23:55 · 00058897 → 智寬　　　展開 ▼

點「展開」才會列出每一次：什麼時候、誰按的、寄給了誰、哪一個階段，一次一行。滑鼠移上去可以看到那一封的完整內容（收件者信箱、副本、寄件者）。標題列也會多一個 ✉ 已通知 N 次。

為什麼不放進時間軸：那條時間軸回答的是「這個日期為什麼變了」，而通知回答的是「催過了沒」，是兩件事。實測 7 筆通知會讓軌跡從 365px 撐到 951px，把真正的時程變更擠到要捲四個畫面才看得到。

「已通知 N 次」這個數字本身就有用：催了五次還沒壓日期，那是該找人談的訊號 —— 以前要自己數卡片才知道催過幾次。

⚠️ 紀錄一筆都沒有少，只是換個地方顯示。標了「未確認送出」的那幾次會用紅字標出來，不會被收進去看不見。

寄不出去的時候，系統一定會說原因
  • 「尚未設定郵件伺服器」—— 系統管理者還沒把公司的郵件主機填進設定檔。
  • 「⋯沒有填 EMAIL」—— 那個人在指派人員主檔裡沒有信箱。信箱欄是唯讀的，要請管理者直接在資料庫補上。
  • 「⋯的 EMAIL 格式不正確」—— 那一格有值，但打錯了，訊息會把目前的值直接顯示給你看。最常見的三種：夾雜全形字元（例如全形的 ＠）、兩個信箱用逗號或分號串在一起、從 Outlook 貼過來時把姓名和角括號一起貼進去。同樣要請管理者在資料庫改。
    這種會在按下確認的瞬間就擋下來，不會等到連上郵件主機才失敗。
  • 「負責人還沒指派」—— 這筆需求那一邊的負責人是空的，請先在編輯視窗指派。
  • 「找不到可用的寄件者信箱」—— 你的工號不在指派人員主檔裡，而管理者也沒有設系統共用信箱。請補上其中一個。
  • 副本找不到信箱時照樣會寄給主要收件者，只是沒有副本，並且會另外跟你說一聲。

按下「確認」之後畫面上會先出現「寄送中…」。這是整個系統裡唯一要等外部伺服器回應的動作，正常幾秒內就會有結果；連不到郵件主機時最多等 20 秒，然後會告訴你連不到、以及該請 IT 檢查什麼。沒有看到任何結果訊息就代表還沒寄出去，不要重複按。

偶爾會出現第三種結果：「尚未確認送出」。這代表信已經交給郵件系統，但系統在時限內還沒能確認它真的送出去了（可能還在重試，也可能會失敗）。這種情況軌跡那一筆會標上「未確認送出」以示區別 —— 過一下請確認對方有沒有收到，沒收到就再按一次 ✉。這不算「已寄出」，系統刻意不會用那三個字騙你，下次存檔也還是會問你要不要通知。

郵件主機接了連線卻遲遲不回應時也會走到這一種：等滿設定的秒數之後就不再等，並照實說「這封信可能已經寄出，也可能沒有」。請先去確認對方收到了沒，不要直接再按一次 —— 那有機會讓對方收到兩封。

最後還有一種很少見的：「等太久，已停止等待」（超過 90 秒）。畫面不等了，但不代表信沒寄出。請按頁首的重新整理，看那筆需求的「時程變更軌跡」有沒有多一列「通知寄送」：有就是已經寄出，沒有才需要再按一次。

「通知寄送」不算時程異動：它不會讓資料列多掛一個 ⚠，也不會影響任何統計數字。

什麼情況不預警

  • Status = Done，或 StatusID = 5（結案）—— 整筆不預警。
  • 階段已被下一階段接手 —— 也就是 StatusID 已經走到它後面（例如 StatusID 是 3，① ② 就算走完了）。那不是風險。
    ⚠ 「走完了沒」只看 StatusID，不會因為你先把後面的日期壓好就當成前面走完了。StatusID 還在 1、卻把 ①②③ 三個日期一次先填好時，① 照樣會標逾期 —— 要讓它不再亮，請用「標記完成…」把 ① 記成完成。（只有 StatusID 空白的舊資料才會用「② 有日期」去推 ① 已完成。）
  • 該階段有「實際完成日」—— 已經走完了。
  • 未走完的階段全都還沒壓日期、而且 StatusID 也推不出當前階段 —— 沒有可盯的到期日就不預警，精簡模式那一欄會顯示「未排定」。

「逾期」下拉的四個選項

選項包含什麼
需關注未壓日期 + 已逾期 + 7 日內到期，全部。
已到階段未壓日期只看上面那個 ⚠ 未壓日期。
已逾期到期日已經過去。
7 日內到期還沒到期，但剩 7 天以內。

7 日的窗只限制「尚未到期」的項目；已逾期與未壓日期的一律列入。

KPI 卡（五張，全部可點）

卡片點下去會發生什麼

件數為 0 的卡不給點（點了只會看到空表格）。風險預警卡列出需關注的明細，點其中一筆會切到需求列表、套上篩選並自動展開那一列。

各年月 × 目前階段案件數

列＝五個階段，欄＝年月，右側「合計」欄、底部「合計」列。

  • 分組的年月是註冊年月，與下方的趨勢圖完全相同 —— 所以合計列的每一格必然等於下方那根柱子的總高。
  • 0 一律留白不寫 0：有值的格子才跳得出來。
  • 1~5 五列固定都出現（0 件也要看得到「這一階段是空的」）。推不出階段的資料歸「— 未分類」列。

年月區間

控制項只放在交叉表的標題列，下方的趨勢圖與它連動。兩個下拉（起／迄）＋三顆預設鈕（近 6 月／近 12 月／全部）。預設是最近 12 個有資料的年月（不是日曆月 —— 資料本來就會斷月）。起訖選反了會把另一端一起帶過去，不會讓畫面直接空掉。

各年月案件數（趨勢圖）

數字直接標在柱子上：總數在柱子正上方，進行中／已完成分別印在自己的色塊中央 —— 這張圖會投在會議室的牆上，台下沒有滑鼠可以 hover。底部會寫出目前的區間與該區間的總件數。

人員負載（進行中案件數）

EMS 與 MSD 兩側各自把目前尚未結案的案件依負責人分堆，兩側共用同一個長度基準（所以兩邊的長條可以互相比較）。沒填負責人的歸「未指派」。兩側各自加總都等於 KPI 卡的「進行中」。

這張卡不跟年月區間連動（標題右邊寫著「不分區間」）

它回答的是「現在誰身上壓著幾件」，是當下的快照；而年月區間是依註冊年月分組的。把區間套上去會變成「某段期間註冊、而且目前仍未結案」的混合數字 —— 那不是任何人會問的問題，也會讓兩側的加總不再等於「進行中」。

它排在整頁的最後一張：上面三張（交叉表、區間選擇器、趨勢圖）是同一個口徑、同一個區間，這一張是「現況」——上半部看區間、最後一段看現況。

精簡模式（主管檢視）

從 16 欄收到 9 欄：No、NID、專案名稱、子項目分類、EMS、MSD、StatusID、目前階段時程、現況描述。

  • 四個階段的日期欄併成一欄「目前階段時程」，顯示第 10 章那套規則挑出來的階段 —— 所以這一欄的紅字必然對得上「需關注」的數字。
  • 7 日以外的項目改用灰字顯示「剩 N 天」（顏色只留給異常）。
  • 完整的四階段時程仍在展開明細裡，資訊沒有消失。
  • 視窗寬度 ≤ 1024px 時自動套用，開關上會標「· 窄螢幕」。把視窗拉寬就回到你原本的設定。
  • 放大（瀏覽器縮放／字級）不會自動幫你切到精簡模式 —— 那時整個版面會跟著一起變寬，用橫向捲動看完整的 16 欄（見下一節）。

字級

頁首的 Ａ 100% 循環 100% → 115% → 130%，設定會被記住。資料列的字很小（10~11px），這顆讓你在自己的桌機上整片放大。

放大之後右邊放不下，會怎麼樣？

可用寬度 = 視窗寬 ÷ 放大倍率（瀏覽器的 Ctrl＋滾輪縮放也一樣）。16 欄的表格壓縮到極限是 約 1256px（整頁需要 1281px），低於這個數字就需要橫向捲動才看得到最右邊那幾欄。

這時整個版面會跟著一起變寬 —— 頁首、工具列、統計卡、圖例列都會長到和表格一樣寬，往右捲時整頁一起平移。所以不會再出現「表格還在延伸、上面的卡片卻切在半空中」那種破圖，也不會因為放大就自動把欄位收起來（16 欄永遠是 16 欄，除非你自己開精簡模式）。

需要橫捲時不會跳任何提示 —— 瀏覽器下方的橫向捲軸本來就在告訴你右邊還有內容，再多一顆紅色警告只會擋到畫面（⚠ 右邊被切掉 那顆現在只保留給投影模式，因為台上的人看自己的螢幕，不會發現布幕右邊少了幾欄）。

不想橫捲的話，隨時可以自己降字級、把瀏覽器縮放調回 100%（Ctrl + 0）、切精簡模式，或把視窗拉寬。系統不會自動幫你改設定。

投影模式

頁首的 📽 投影。它不是第三套版面，只是把既有畫面調到會議室看得見的程度：整體放大（預設 150%，可調 125／140／150／175／200%）、提高對比、加上斑馬紋，並自動切到淺色底（投影機黑階偏灰）。

情境行為
還沒開精簡模式📽 投影 是停用的 —— 16 欄放大後一定橫向捲。請先按「精簡模式」。
在統計報表頁📽 投影 停用（那頁是圖表，放大會把圖擠扁）。

13Excel 匯出與匯入

工具列的 Excel 鈕展開。兩個功能的風險差很多，所以刻意分開呈現。

↓ 匯出 Excel

把目前資料庫的狀態下載成 .xlsx。匯出的表頭與匯入的對應名稱一致，匯出的檔案可以原封不動匯回來。

匯出的一律是全部，不是你篩出來的那幾筆

搜尋、篩選、排序完全不影響匯出 —— 不管畫面上顯示幾筆，下載到的都是全部未刪除的需求。按鈕底下那行字會寫出實際會下載幾筆；畫面上有篩選時還會多一句提醒目前畫面是幾筆。

只要篩出來的那幾筆，請下載之後在 Excel 裡自行篩選。

⚠ 匯入 Excel

匯入會清空整張表

匯入不是以 NID 比對更新，而是清空整張表後以檔案內容重建。這是測試階段的刻意做法。會跳確認視窗，請確認你選的是正確的檔案。

檔案裡沒有的東西不會回來：全部的時程變更軌跡（⚠N、明細的軌跡、完整軌跡）、四個階段的實際完成日、延期／提早／規格回退的次數（⏰、🔄）、通知寄送的紀錄，匯入後全部歸零。匯出檔雖然帶著實際完成日與次數欄，匯入時也刻意不讀（那些是稽核表的快取，稽核表清了它們就不該留著）。確認視窗會把這幾條列出來。

清空之前系統會先做四道檢查，任何一道沒過就整個中止、資料不動：

  • 檔案打不開
  • 找不到表頭列，或關鍵欄位都對應不到
  • 一列資料都讀不出來
  • 檔案內有重複的 NID

匯入成功後會顯示匯入了幾筆。若有欄位對應不到，訊息會列出對應不到的欄名清單 —— 那串字值得抄下來，Toast 的停留時間會依字數自動加長（最多 12 秒），也可以按 ✕ 手動關掉。

四個「實際完成日」欄位與三個計數欄會匯出但不會被匯入吃回去，避免重灌時撞欄。

新增允許規則五個條件欄：工號、DEPTNAME（完整部門路徑，如 12A_PTI/ESI/MSD）、DEPT_1 / 2 / 3（三層部門）。任填一欄以上，再加選填的備註。
目前允許規則每條規則以晶片顯示條件，右側 🗑 刪除。建立者與時間在 tooltip。
以工號測試規則輸入任何工號，看他會不會被擋、名冊上是誰、屬於哪個部門、被擋的原因。不受總開關影響 —— 開卡控之前先用幾個工號試過。
管理者可以開這個面板的人。新增（工號＋備註）、移除；自己那一列的 🗑 是灰的。
最近異動展開可看最近 30 筆：誰在什麼時候新增／刪除了哪條規則、開了或關了卡控、加了或移除了哪位管理者。

規則怎麼比對

  • 同一條規則內填了多個欄位＝全部符合才通過（且）。例：DEPT_2=ESI 且 DEPT_3=MSD。
  • 多條規則之間任一符合即放行（或）。例：一條 DEPT_3=MSD、一條 工號=00058897，兩種人都能看。
  • 只填工號＝白名單，不查名冊也放行。名冊臨時查不到時，這種規則照常有效。
  • 最常見的設法：一條 DEPT_3=MSD（MSD 全員）＋ 幾條 EMS 窗口的工號。
建議的開啟順序

① 先新增規則 → ② 用「以工號測試」拿幾個實際的工號驗過（該過的過、該擋的擋）→ ③ 再按 開啟卡控。規則與開關的變更於下一次進站或重新整理時生效，已經在瀏覽中的人不會被中途踢出。

被擋的人會看到什麼

整頁只剩一張「🚫 無權限瀏覽此頁面」卡片：登入工號、名冊上的姓名與部門、被擋的原因（不在名冊／部門與工號皆不符／名冊查詢失敗），沒有頁首、也不會載入任何需求資料。請他把那張卡截圖給管理者，管理者依上面的部門或工號加規則即可。

三種「被擋」的原因不一樣，找的人也不一樣

不在人員名冊中：名冊裡沒有這個工號 —— 用「工號」白名單直接放他進來。部門與工號皆不符合：名冊查得到但沒有規則收他 —— 加部門或工號規則。人員名冊查詢失敗：這不是規則的問題，是名冊那張表連不上（跨伺服器），請聯絡系統維護人員；在那之前只有「工號白名單」的規則還能放人。

卡控擋的是「畫面」

卡控開著時，不符合規則的人看不到任何一列資料。它不影響 Excel 匯出檔的傳遞、寄信通知，也不影響管理者在後台的操作。

15疑難排解

日期欄位是灰的，改不動

看鎖頭的樣子：「🔒 已鎖定，點此修改」代表這階段已經有日期，點一下就解鎖。灰色實心、點不動的鎖頭代表前一階段的結束日還沒填 —— 補完前一階段，這一階段會立刻開放（見第 4 章）。

「標記完成…」鈕不見了

鈕的位置會改顯示一句灰字說明為什麼。四種原因與處理方式列在第 5 章的表格裡。

畫面上沒有「延期」這個功能，為什麼「警示」下拉有「有延期完成」？

「延期完成」不是一個獨立的按鈕，它是你按下 「標記完成…」時填的那個完成日 已經超過原訂結束日的判定結果，系統就把它記成延期完成並讓 ⏰ 次數加一。所以篩選的是「曾經延期完成過」的需求。

存檔時說「這筆資料已被其他人修改」

你打開編輯視窗之後，有別人先存了同一筆。系統擋下來以免你的存檔把對方的改動蓋掉。請按頁首的 ⟳ 重新整理（篩選與排序會保留），重新打開這筆確認對方改了什麼，再重做你的修改。

我的需求不見了／一進來只有十幾筆

需求列表預設只顯示尚未結案的。已結案的沒有被刪掉，把工具列的 進度 改成「不限進度」、或按階段統計鈕的 ALL、或直接按 5 結案 就會出現（第 9 章）。

搜尋時若有結案的需求符合，晶片列會直接出現「另有 N 筆…」與 一併顯示，不必自己去找開關。

筆數變少了，可是工具列上看不到我設了什麼條件

看表格正上方的條件晶片列，每一個生效中的條件都在那裡（包含系統預設的「進度：進行中」），每顆都能單獨移除。

特別留意標成紅框的晶片 —— 那是「目前模式下被收起來的欄位」的篩選值，看不到卻仍在過濾（第 9 章）。

版面跑掉了，標題和搜尋框滑到畫面外面

表格橫向超出視窗了，整頁跟著橫捲。頁首、工具列與卡片會跟著一起變寬並一起平移，所以捲到哪裡版面都是完整的 —— 若看到卡片邊緣切在半空中，代表你手上是舊版，請重新整理（Ctrl + F5）。

要回到不必橫捲的畫面：降字級、把瀏覽器縮放調回 100%（Ctrl + 0）、切精簡模式，或把視窗拉寬。

新增需求時說「必填欄位未完成」，可是我都填了

檢查 EMS 負責人的下拉是不是空的。那個下拉的名單來自人員主檔，讀取失敗時下拉底下會出現紅字提示「指派人員名單讀取失敗」。請重新整理頁面；若持續失敗，代表後端讀不到人員資料，請找系統管理者。

展開明細看不到任何變更紀錄，統計報表的「時程異動」是 0

先看 KPI 卡上是不是顯示 「—」 而不是 0，以及圖例列有沒有寫「讀取失敗，不代表沒有變更」。有的話是稽核軌跡讀取失敗，不是這批需求真的沒被改過。請重新整理。

某一列左邊有紅色風險條，可是四個日期欄一格紅字都沒有

多半是「⚠ 未壓日期」：StatusID 已經走到某一階段，而那一階段自己還沒排日期。那一格會有紅色的「⚠ 未壓日期」徽章。哪一階段看同一列的 StatusID 欄（未壓日期的定義就是「StatusID 走到的那一階段自己沒排日期」，兩者必然相同），或把滑鼠移到徽章上。

兩個人同時在改，會不會蓋掉彼此？

不會。系統有樂觀鎖，後存的那個人會收到「已被其他人修改」的提示（見上面那則）。另外連按儲存也只會送出一次 —— 按鈕在處理期間是停用的。

我按了 F5，篩選和展開的列全部不見了

那是 F5 的行為。要保留現場請用頁首的 ⟳ 重新整理 鈕 —— 它會重讀需求與軌跡，但保留篩選、排序與展開狀態。（篩選與排序其實有寫進網址，F5 之後會回來；展開的列不會。）
